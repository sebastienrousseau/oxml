# 0.0.5

`XPath` 1.0, finished. The previous release claimed a complete `XPath`
implementation; this one is the first where that is true.

## If you are upgrading

**An expression that silently returned nothing may now be an error.**
That is the point, but it is a behaviour change and it is the one to
check.

Before this release, a function name the engine did not implement
compiled and evaluated to an empty node-set. Six functions the
specification requires were among them, so `substring-before(...)`,
`translate(...)`, `name(...)`, `id(...)`, `lang(...)` and
`substring-after(...)` all answered `""` — indistinguishable from a
document with no match.

Argument counts were not checked either, and those answers looked more
convincing still:

| Expression | Before | Now |
|---|---|---|
| `starts-with("abc")` | `true` | compile error |
| `translate("abc", "ab")` | `"c"` | compile error |
| `substring-before("a")` | `""` | compile error |

`starts-with("abc")` was `true` because the absent second argument read
as the empty string, and every string starts with that.

If you have an expression with a typo or a wrong argument count, it
compiled before and does not now. If you have one using any of the six
functions, it returned nothing before and works now.

**`Document::len()` is one higher.** `xml` is bound by specification for
every element, so the root element carries a namespace node for it. A
document with no namespace declarations at all still has that one node.

## Added

- **All 27 `XPath` 1.0 functions.** `substring-before`,
  `substring-after`, `translate`, `name`, `id` and `lang` were missing.
- **All 13 axes.** `following`, `preceding` and `namespace` were
  missing. The roadmap called `XPath` complete on the strength of the
  function library alone; it was not.
- **`Document::prefix`**, the prefix an interned name was written with.
  `name()` needs it, and namespace resolution discards it.
- **`Document::element_by_id`**, the element carrying an `ID`-typed
  attribute. An attribute is an ID because `<!ATTLIST>` declared it
  one, not because it is spelled `id`; a document with no DTD has no
  IDs, and `id()` there is correctly empty.
- **`Document::namespace_nodes`** and `NodeKind::Namespace`.
- Three benchmark groups — `encoding`, `tree`, `entities` — covering
  capabilities that had none. 7 benchmarks to 19.
- An `external_entities` example. `parse_with_external` had counted as
  covered only because `parse_with` delegates to it internally.

## Fixed

- **Unknown function names and wrong argument counts are compile
  errors** rather than plausible-looking empty results.
- **`name()` reports the prefix.** Interned names now carry the prefix
  they were written with, which means interned ids distinguish
  prefixes — so duplicate-attribute detection compares *names* rather
  than ids. Without that, `p:x` and `q:x` with both prefixes bound to
  one namespace stopped colliding, which Namespaces in XML forbids.
  The W3C suite caught it as four named regressions.
- **An undeclaration (`xmlns=""`) shadows an ancestor's binding.**
  Recorded as a declaration with an empty URI, because a prefix that is
  simply absent leaves the ancestor's binding in scope.

## Documentation

Every claim in the README was checked against the code. What that
found, in short: a benchmark table publishing six absolute timings
against the repository's own stated rule; a benchmark documented under
a name it had been renamed away from; `CONFORMANCE.md` stating two
different pass rates in one file; a per-submission table understating
`xmltest` by eight points; and each README carrying broken links the
other did not, because they are byte-identical but sit at different
depths.

Four checks were added so none of it drifts again: markdown links
resolve, the benchmark table names benchmarks that exist, the README
publishes no bare timing, and `doc/` conformance figures are compared
against the harness output.

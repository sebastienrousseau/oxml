# oxml 0.0.12

Release preparation dated 2026-10-31. This file does not announce a
publication or authorize a tag.

## Highlights ⭐️

* **Family version alignment**: Advance the core library, conformance helper, and fuzz harness to 0.0.12 in lockstep with the rest of the oxml suite, and refresh the root and fuzz dependency lockfiles.
* **Release SBOM and source-commit verification**: Fix the single-quoted `jq` filter and remove the unsupported `-p` flag from `cargo cyclonedx` in the post-publish `release-page` job, pinned by executable regression contracts.
* **Scorecard SARIF parity on pull requests**: Populate empty `supply-chain/branch-protection` and `supply-chain/online-scm` SARIF configurations on pull-request Scorecard runs so GitHub Code Scanning compares all three Scorecard categories against `main`.

## Upgrade notes

- Rust 1.89.0 or newer is required. Pre-0.1 releases may break API,
  as documented in the [MSRV policy](../MSRV-AND-DEPRECATION.md).
- All family packages share version 0.0.12, including unpublished
  fuzz and conformance harnesses, which remain non-publishable.

## Verification and release status

Scorecard executes a provenance-verified, digest-pinned upstream image.
Scans retain SARIF artifacts and categorized GitHub code-scanning results;
they do not publish to Scorecard's public service. The README badge tracks
workflow status rather than a public score. Posture findings remain
actionable even when the scan itself succeeds.

The fuzz policy permits NCSA only for libfuzzer-sys 0.4.13; it does not
extend the runtime license allowlist. Security CI checks both graphs.

The [changelog](../../CHANGELOG.md#0012---2026-10-31) contains the full
change list. The core's local gate, package inspection and dependency
checks must pass on the final release commit; CI must be rechecked
after the release-preparation commit is pushed.

Publish `oxml` before `xmlschema`, and publish `oxml-json` before
`oxml-lsp`. The complete dependency order is in
[RELEASING.md](../RELEASING.md). No tag or registry publish is part of
this preparation. The release workflow generates the merged-PR list,
asset checksums and comparison link from the actual published artifacts.
